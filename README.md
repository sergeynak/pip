# Pip

Flutter-клиент студии [Pip](https://pip.kz). Приложение получает услуги, проекты, статьи и контакты из существующей CMS через `https://pip.kz/api/v1`. Форма отправляет заявки в ту же CMS. Основные платформы проекта — Android и iOS; Web подходит для просмотра и проверки интерфейса.

Обычный запуск использует рабочее API. Демонстрационные данные включаются только отдельным параметром. Свой сервер, база данных и вход в аккаунт для публичного каталога не нужны.

Код разделён по понятным задачам: запуск, приложение, экраны, запросы и модели данных. Комментарии в коде объясняют действия на русском языке. Начать знакомство удобно с [короткой инструкции для новичка](docs/architecture.md).

## Возможности

- Главная, каталог услуг и подробные страницы с ценами и описаниями.
- Портфолио с поиском, загрузкой следующих страниц, галереей и просмотром изображений с масштабированием.
- Блог со списком и полным текстом статьи.
- Контакты из настроек сайта и открытие внешних ссылок.
- Форма заявки: имя, контакт, услуги из `/config`, необязательное описание задачи.
- Состояния загрузки, пустого списка, ошибки и повторной попытки.

Полный текст и галерея загружаются отдельным запросом при открытии карточки. Подтверждение заявки появляется только после `201` с `accepted: true` и ID заявки. Демо-режим заявки не отправляет.

Основные вкладки и страницы деталей поддерживают обновление жестом вниз. Поиск отправляется после короткой паузы ввода; запоздалый ответ старого запроса не заменяет новый результат.

## Запуск

Для этой версии проекта используется Flutter **3.47.7**, включающий Dart **3.13.5**.

```sh
flutter pub get
flutter run
```

Просмотр в браузере:

```sh
flutter run -d chrome --web-port=5173
```

Для чтения данных с рабочего API дополнительных параметров не требуется. Браузерная отправка заявки разрешена только с доверенного origin: `http://localhost:5173` должен быть отдельно разрешён на сервере в `MOBILE_API_ORIGINS`. Без этого чтение может работать, а отправка — отклоняться. Подробнее в [инструкции по API](docs/api-integration.md#браузер-и-cors).

Другой адрес API и демонстрационный режим:

```sh
flutter run --dart-define=API_BASE_URL=https://example.com/api/v1
flutter run --dart-define=USE_DEMO_DATA=true
```

Параметры `--dart-define` задаются при запуске или сборке. В них нет секретов; административные токены и пароли приложению не нужны.

## Проверки и сборка

```sh
dart format --output=none --set-exit-if-changed lib test tool
flutter analyze
flutter test
flutter build web --release
```

Тесты подменяют HTTP-клиент или `ApiService`: они проверяют ответы API и интерфейс без создания заявок на рабочем сайте. Успешная Web-сборка сама по себе не подтверждает работу нативной сборки на телефоне.

Отдельная проверка чтения рабочего API:

```sh
dart run tool/check_api.dart
```

Она выполняет только GET: настройки, услуги и детали, проекты и следующая страница, избранные проекты, статьи и детали. Реальный POST в CMS не отправляется.

Для APK дополнительно нужны JDK и Android SDK; для iOS — macOS и Xcode. Команда после настройки Android:

```sh
flutter build apk --debug
```

Ожидаемый путь результата — `build/app/outputs/flutter-apk/app-debug.apk`. Идентификатор приложения — `kz.pip.pip`. Публикация в магазинах требует настройки релизной подписи, иконок и проверки на устройствах.

## Пять основных мест в коде

| Путь | Назначение |
| --- | --- |
| `lib/main.dart` | Выбор `ApiService` или `DemoApiService` и запуск `PipApp` |
| `lib/app.dart` | Тема, меню и переключение вкладок; освобождение API-клиента в `dispose` |
| `lib/screens/` | Отдельные файлы экранов каталога, проектов, блога, контактов и заявки |
| `lib/api/` | `ApiService` с запросами данных, `ApiClient` с HTTP и JSON, настройки и демо-примеры |
| `lib/models.dart` | Простые классы для проекта, статьи, услуги, заявки и ошибки `AppException` |

Общие элементы интерфейса находятся в `lib/widgets/common_widgets.dart`, проверки — в `test/`, сценарий чтения рабочего API — в `tool/check_api.dart`.

Путь запроса: `main → app → экран → ApiService → ApiClient → API`. Экраны вызывают конкретные методы вроде `getProjects` и `sendBrief`. Страницы нумеруются обычными числами: `page: 1`, `page: 2`; `nextPage: null` означает, что следующей страницы нет.
